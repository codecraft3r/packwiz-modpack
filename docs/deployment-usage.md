# Modpack Deployment & Usage Guide

This guide is intended for developers and maintainers of the modpack. It covers how to trigger a release and how to use the generated artifacts for local testing, development, and production server deployment.

## 1. Triggering a Release

The project uses GitHub Actions to automate the creation of Modrinth (`.mrpack`), CurseForge (`.zip`), and MultiMC artifacts whenever a new version is tagged. 

> [!NOTE]
> Because clients (via MultiMC/Prism) and the server use auto-updating setups based on the `pack.toml` file, downloading the raw zip files from GitHub Releases is usually unnecessary for regular updates. However, these assets remain essential for users who do not want auto-updates, cannot use Prism, or are performing an initial setup. The pipeline also ensures these files are ready for public Modrinth/CurseForge uploads.

To trigger a new release, simply push a new tag to the repository following SemVer guidelines (`vX.Y.Z`):

```sh
git commit -m "release: v1.0.1"
git tag v1.0.1
git push origin main --tags
```

This will trigger the `Release Modpack` action which builds and uploads the artifacts.

## 2. Consuming Client Outputs (Testing)

If you need to test the client locally, you can use the artifacts generated by the deployment pipeline.

### Prism Launcher / MultiMC

The pipeline generates an auto-updating MultiMC instance zip (`All the Mons-MultiMC-Instance.zip`). This is the recommended way to test the pack locally, as it behaves exactly like a player's setup.

1. Download the `All the Mons-MultiMC-Instance.zip` from the latest GitHub Release.
2. In Prism Launcher or MultiMC, drag and drop the zip into the launcher window, or click **Add Instance** -> **Import from zip**.
3. Launch the game. The embedded `packwiz-installer-bootstrap` will automatically pull the latest `pack.toml` and sync the mods/configs to your instance before the game starts.

### Modrinth App

For testing the Modrinth format, you can use the generated `.mrpack` file:

1. Download the `All the Mons.mrpack` file from the latest GitHub Release.
2. Open the Modrinth App.
3. Click the `+` icon to create a new profile, and select **From File**.
4. Select the `.mrpack` file to import the profile.

## 3. Server Environments

The modpack is designed to be hosted via Docker for local development and Pterodactyl for production. Both methods rely on the packwiz auto-installer to keep the server synchronized with the GitHub repository.

### Local Dev Server (Docker)

To test the server locally and ensure there are no server-incompatible mods, you can use the provided `docker-compose.yml`.

1. Ensure Docker and Docker Compose are installed on your machine.
2. Open a terminal in the root of the repository.
3. Run the following command to start the server in the background:
   ```sh
   docker-compose up -d
   ```
4. The server will download the neo-forge server jar, run the packwiz installer to fetch all server-side mods, and start up. You can connect at `localhost:25565`.
5. To view logs, run `docker-compose logs -f`.

> [!TIP]
> The `docker-compose.yml` points to the `pack.toml` file hosted on GitHub. If you are testing changes on a specific branch, temporarily update the `PACKWIZ_URL` environment variable in `docker-compose.yml` to point to the raw URL of your branch before starting the container.

### Production Server (Pterodactyl)

For the live production server, we use Pterodactyl with a custom packwiz auto-installer egg.

Since the server relies on the auto-installer:
1. You do **not** need to manually upload mods to the server via SFTP.
2. Simply restart the server from the Pterodactyl panel.
3. Upon startup, the custom egg's startup script will invoke the packwiz installer, which compares the server's files against the repository's `pack.toml` and automatically downloads, updates, or deletes files as necessary.

> [!IMPORTANT]
> Ensure the Pterodactyl server's startup parameters have the `PACKWIZ_URL` pointing to the `main` branch of this repository so it receives the latest pushed updates.

## 4. Using the GitHub Repo with Packwiz

If you want to manually modify the modpack (add mods, update versions, or tweak configs) without relying on automated helpers, you can use the `packwiz` CLI directly in the cloned repository:

1. **Clone the repository**:
   ```sh
   git clone https://github.com/codecraft3r/packwiz-modpack.git
   cd packwiz-modpack
   ```
2. **Setup Pre-commit Hooks (Required)**:
   To ensure your `index.toml` is always up-to-date, we enforce a validation check in CI. Configure your local Git to use our provided hooks:
   ```sh
   git config core.hooksPath .githooks
   ```
3. **Install Packwiz**: Follow the [installation instructions](https://packwiz.infra.link/tutorials/installing/) (e.g., `go install github.com/packwiz/packwiz@latest`).
4. **Make Changes**:
   - Add a mod: `packwiz modrinth install <mod-name>` or `packwiz curseforge install <mod-name>`
   - Update all mods: `packwiz update --all`
   - Remove a mod: `packwiz remove <mod-name>`
5. **Refresh**: After manual edits (like tweaking config files in the `config/` folder), always run:
   ```sh
   packwiz refresh
   ```
   *(Note: The pre-commit hook will also run this automatically when you commit.)*
6. **Commit & Push**: Commit the modified `.toml` files and push to GitHub. If you are ready to publish, tag the commit as described in Section 1.
